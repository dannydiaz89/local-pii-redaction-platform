# Project governance

## Maintainer

## Decision process

Routine changes are accepted through review after automated quality gates pass. Security,
contract, privacy, redaction, verification, and licensing changes require explicit maintainer
approval. Architectural changes update the relevant ADR before implementation diverges from the
accepted design.

The project aims for written, evidence-backed decisions. The maintainer may delegate areas to
additional maintainers as the contributor community grows. Governance changes are made publicly
and retain repository history.

## Contributions

Contributors retain copyright in their contributions and license them to recipients under the
project license. A contributor agreement may be introduced before accepting substantial external
contributions if future stewardship or dual licensing requires it; it will not be applied
retroactively without contributor consent.

## Releases

Only the maintainer or a delegated release manager may publish official releases. A release must
pass the documented contract, security, privacy, verification, and provenance gates. Forks must
not present themselves as official releases of this project.
